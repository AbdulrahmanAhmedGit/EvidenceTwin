# Current architecture

Current behavior, reviewed 2026-11-08. The approved hosted/scientific requirements in [the brief](../concepts_brief.md) remain a target; this guide describes the implemented local application.

React 19.3 / Router 7.18 / Vite 8 uses route splitting, React Query and domain adapters. `ResearchEntry`, `ResearchCases` and `CaseDataset` implement one chart-first case journey with optional questions and supporting evidence. `cases-api.ts` validates its wire payloads; existing analysis/evidence/Council/audit/report adapters retain inspection journeys. `SessionGate` establishes a principal before selecting an account draft. Ordinary settings exclude provider credentials; operator settings remain server-authorized.

Flask 3.1 factory installs transport blueprints and runtime services. `services/access.py` establishes the local operator or optional invited principal. `research_cases.py` owns case/revision operations. `runtime.py` handles bounded ingestion and authorized legacy operations. `workflow.py` runs exploratory model reviews in a bounded thread pool. Provider calls and credentials remain server-side; packaged prompts define model behavior, not scientific proof.

`Store` uses a private SQLite database of `(kind,id,body)` JSON records plus generated-ID upload directories. Original `analysis`/`benchmark` records remain; `research_case`, `case_revision`, `account` and `login_limit` add case and access state. Revisions preserve bytes, names and SHA-256 hashes; analysis inputs are copied from the accepted revision. Case/revision writes commit together; accepted case/run request receipts and analysis records commit together. Local locks coordinate one application process. No destructive database migration or silent ownership import occurs.

All records/files/reports/jobs are checked server-side. Case-linked analyses/reports cannot be deleted through the legacy deletion API. Legacy unassigned rows are operator-only; newly saved accounts-disabled rows belong to `local`. Enabling accounts does not transfer them to an invited account. See [rollback](DEPLOYMENT_ROLLBACK.md).

The independent `backend/evidencetwin_backend/execution/` package implements isolated PostgreSQL infrastructure using SQLAlchemy Core, Psycopg and Alembic. HTTP submissions do not use it. Its worker requires reviewed adapters; it is not a configured hosted service. See the preserved [backend handoff](../backend/README.md) and [scientific scope](SCIENTIFIC_SCOPE.md). Do not infer multi-process safety, durable hosted execution or completed scientific checks from its isolated tests.

`science/` is a Flask-independent bounded evidence layer. It performs complete-table exact queries, scoped Decimal arithmetic, public-source snapshots and versioned packet preparation. Workflow workers invoke it before independent reviewers and can satisfy a single bounded query round per specialist. Raw outputs, pinned prompt snapshots and per-role inputs remain in the local JSON records. Read-only processing/query endpoints retain server ownership checks. This is distinct from the planned validated Scientific Core and PostgreSQL execution cutover. See [evidence processing](EVIDENCE_PROCESSING.md).
